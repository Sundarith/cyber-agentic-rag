Five-stage retrieval grounds the routed local models

Hybrid search finds candidates, authoritative bridges inject known mappings, the rerank stack discriminates sibling CWEs, then the router sends mapped CVEs to Granite and unmapped CVEs to Foundation-Sec. Routed ensemble: 864/1000 = 86.4% on CTI-Bench RCM.

Why hybrid retrievalBM25 catches exact CVE/CWE IDs; BGE embeddings catch paraphrases. Equal weighting beats either alone.
Why bridge injectionNVD already assigns CWEs to 150k CVEs. Direct injection beats semantic guessing when ground truth exists.
Runtime routingThe system sends mapped CVEs to Granite 4.1 8B and unmapped CVEs to Foundation-Sec-8B-Reasoning on separate vLLM endpoints.

CTI-RAG performance by NVD mapping status

This split explains where the 86.4% routed ensemble comes from: mapped CVEs benefit from NVD structured CWE bridge lookup, while unmapped CVEs require description-based CWE inference.

Mapped CVEs903 of 1000 benchmark CVEs have an official NVD CWE assignment. Retrieval finds the matching CVE description and bridge-injects the structured CWE.
Unmapped CVEs97 CVEs have no NVD CWE assignment. Foundation-Sec handles the description-only reasoning slot best among tested local models.
InterpretationMapped performance is retrieval-plus-lookup strength; unmapped performance is CWE taxonomy generalization.

Clean techniques that improved unmapped CVE mapping

For NVD-unmapped CVEs, there is no structured CWE label to copy. These changes improve candidate confidence and final CWE selection.

What improvedThe system became more careful about when k-NN can override context, then added an official alias selector for cases where the correct CWE is already retrieved.
What stayed cleanThe phrase dictionary is generated for all CWEs from raw MITRE CWE XML, not from CTI-Bench failures.
ResultNVD-unmapped accuracy improved from 61/97 to 68/97, or 62.9% to 70.1%.

Raw data sources behind CTI-RAG

The system uses public MITRE and NVD datasets as its knowledge base, and CTI-Bench only as the evaluation benchmark.

MITRE ATT&CK

Public adversary behavior knowledge base. We use it for groups, malware/tools, techniques, tactics, and mitigations.

https://github.com/mitre-attack/attack-stix-data

MITRE CAPEC

Public attack pattern catalog. We use it for CAPEC attack patterns and mappings into other MITRE taxonomies.

https://capec.mitre.org/data/downloads

MITRE CWE

Public software weakness taxonomy. We use it for CWE weakness definitions, hierarchy, and mitigation text.

https://cwe.mitre.org/data/downloads

NVD CVE Data

Public vulnerability records from NIST NVD. We use CVE descriptions and official CWE assignments from NVD metadata.

https://nvd.nist.gov/vuln/data-feeds

CTI-Bench Paper

Benchmark paper used for model baseline comparison and task framing.

https://arxiv.org/abs/2406.07599

CTI-Bench Dataset

Public benchmark repository. We use CTI-RCM prompts and ground-truth labels for evaluation only, not as retrieval evidence.

https://github.com/xashru/cti-bench

Knowledge sourcesATT&CK, CAPEC, CWE, and NVD are the raw public sources used by the system.
Evaluation sourceCTI-Bench provides the CTI-RCM benchmark prompts and ground-truth CWE labels.
Important distinctionWe are not leaking benchmark answers into retrieval. CTI-Bench is the exam sheet, not the textbook.
